# Steam 游戏记录站（life joy）

> **一句话**：把你自己的 Steam 游戏库做成一个能看数据、能查成就的本地网站。
> 数据全存在你自己硬盘上的一个文件里，不上传任何地方。

这是 [Yamtrack](https://github.com/FuzzyGrim/Yamtrack) 的**深度改造版**，
原版是「电影 / 剧集 / 动漫 / 书籍」的通用追踪器，本项目砍到只剩游戏，
并额外加了成就、中文名、豆瓣导入、临门一脚等一整套东西。
截图待补——跑起来后打开 <http://127.0.0.1:8001> 就是你自己的样子。

---

## 它到底能干什么

### 核心（媒体追踪站的底子）

- 📚 一个私人游戏库，每个游戏能记：评分、状态（已完成 / 进行中 / 已暂停 / 计划中 / 已放弃）、通关日期、备注
- 🔍 搜游戏、按状态筛、按评分排、列表 / 网格两种看法
- 🔗 手动建条目：Steam 上没有的游戏自己加
- 📊 统计页：玩了多少、多少小时、状态分布

### 这个项目独有的（原版没有）

- 🎮 **Steam 游戏库导入**，含**家庭共享库**（共享来的游戏在备注里带「（家庭共享）」字样，方便区分）
- 🏆 **Steam 成就同步**：每个游戏拿了几个 / 一共几个，哪些游戏已经全成就
- 🎯 **`/near-complete`「临门一脚」页**：专门列出「就差几个成就就全成就」的游戏，
  点进去就能看还差哪几个。这是自己加的页面，原版没有
- 🀄 **中文化**：中文游戏名补全、豆瓣中文数据源
- 🎬 **豆瓣电影 / 豆瓣剧集 / 微信读书导入**：从这三个地方的公开数据搬进来
- 🎨 UI 大改：Tailwind 重做、暗色主题、点导航不整页刷新（软导航）
- 🔄 **Steam 令牌全自动续期**：用专用的 Chrome 配置目录存登录态，每天 03:50 自动续，
  登录一次之后不用再管
- 🐕 **看门狗**：每 5 分钟探一下 8001 端口，站点挂了自动拉起来
- 🔁 **导入更靠谱**：导入失败不再"假装成功"；网络失败会在 1 / 2 / 4 小时后自动重试，最多 3 次

> 令牌续期、看门狗、自动导入这三样靠的是**计划任务 + 后台进程**，
> 需要跑一次 `deploy\07_tasks.ps1 -Apply` 才生效。不装也能正常看库，只是这些活儿得手动干。

## 快速开始

> **详细步骤在 [`deploy/README.md`](deploy/README.md)**，那边每条命令都能直接复制粘贴。
> 这里只给最简路线，方便你先知道大概要干什么。

**先确认机器上有这些**（缺一个都跑不起来）：

| 要什么 | 干嘛用的 |
|---|---|
| Python 3.12 | 跑网站本身 |
| Node.js 18+ | 只用来编译样式（Tailwind），编译完就不需要了 |
| Chrome | Steam 令牌自动续期要用它 |
| 3 GB 以上空闲磁盘 | 封面图缓存会长到 1.3 GB 左右 |
| 8001 端口空着 | 网站就开在这个端口 |

**动手前先做一件事：建虚拟环境。**
`.venv` 这个目录**不进仓库**，clone 下来是没有的。在项目根目录跑一次：

```powershell
python -m venv .venv
```

> 虚拟环境 = 给这个项目单开一套独立的 Python，库装在这里，不污染系统里其他的 Python。

然后**五步跑起来**（在项目根目录，用 PowerShell）：

1. **体检**：`deploy\01_check_env.ps1` —— 缺什么它会直接告诉你
2. **装依赖**：`deploy\02_install_deps.ps1 -Apply`
3. **建库**：`deploy\03_setup_db.ps1 -Apply`（库已存在时会先**自动备份**到 `.tools\backups\`）
4. **配密钥**：把 `.env.example` 复制成 `.env`，照着里面的注释填（见下一节）
5. **收静态文件**：`deploy\05_static.ps1 -Apply`

然后双击 **`start-win.vbs`**，等几秒，浏览器打开 <http://127.0.0.1:8001>。

`deploy\` 里一共 8 个编号脚本，**每个默认只检查、不动手**，真要它干活必须加 `-Apply`。
剩下三个是可选的：`06_warm_images.ps1` 预热封面图（约 20 分钟）、
`07_tasks.ps1` 注册计划任务、`08_verify.ps1` 验收体检。

**两件跟"能不能跑起来"直接相关的事**：

- **数据库不进仓库**。`src/db/db.sqlite3` 被 `.gitignore` 排除了，clone 下来是**没有数据**的。
  跑 `deploy\03_setup_db.ps1 -Apply` 建一个空库，然后去网站里用「导入数据」填你自己的库。
- **`.tools\redis\` 那份便携 Redis 是必需的**，删了站点起不来（它负责后台任务排队）。
  好处是 Windows 上原生就能跑，不需要额外装别的运行环境。

## 配置

配置文件是项目根目录的 **`.env`**（纯文本，记事本就能改）。
仓库里给的模板是 **`.env.example`**，复制一份改名成 `.env` 再填。
模板里每个键都有中文注释说明怎么拿，照着填就行。

**两条铁律，踩了站点直接打不开：**

1. **`DB_HOST` 绝对不能设**。
   `DB_HOST` 是「数据库在别的机器上」时用的地址。本项目数据库就是本地一个文件，
   一旦设了这个键，程序会以为你要连远程数据库，立刻报错。整行都不要写。
2. **`DEBUG` 必须保持 `True`**。
   本地开发模式下网站自己负责发样式和图片文件；关掉以后这些文件全部 404，
   页面会变成一张纯文字的"裸网页"。想藏调试工具条请改 `INTERNAL_IPS`，别动 `DEBUG`。

**几个数据源怎么填**（都是免费的）：

| 来源 | 要填什么 | 去哪拿 |
|---|---|---|
| Steam | API Key + 你的 SteamID64 | Key 在 <https://steamcommunity.com/dev/apikey> 免费申请，**永不过期** |
| 豆瓣 | 只要用户 ID | 抓的是公开收藏夹，**不用登录** |
| 微信读书 | API Key（`wrk-` 开头） | <https://weread.qq.com/r/weread-skills>，长期有效 |

## 数据与备份

**所有数据都在一个文件里**：`src\db\db.sqlite3`

**备份 = 复制这一个文件**。就这样，没有别的要备。

小提醒：`stop-win.vbs` 停掉站点、等几秒再复制最稳；站点跑着时复制可能拿到"抄到一半"的库。

封面图缓存另外存在 `.tools\raw\covers\`，删了不丢数据，只是第一次打开会慢，可以重新预热。

## 已知限制（是数据源的限制，不是 bug，别去"修"）

- **成就只有约 35% 的游戏拿得到**。Steam 对不开放成就数据的游戏直接返回 403，
  这类游戏成就栏永远是空的，怪不了程序。
- **中文游戏名只有约 9%**。Steam 商店本身就没给这些游戏做中文标题，程序无从抄。
- **原版自带的部分测试要连真实外网**（TMDB / IGDB / OpenLibrary 等），断网会失败。
  那是原版留下的测试，不是你的部署出了问题。
- **只在 Windows 上验证过**。Celery（后台任务队列）在 Windows 上必须用 `--pool solo`
  单线程模式跑，定时器（beat）还得单独起一个进程，这些都在启动脚本里配好了，别手改。

## 常见问题

**Q：双击 `start-win.vbs` 没反应？**
它本来就是**静默启动**，故意不弹黑窗口。等 5～10 秒直接开 <http://127.0.0.1:8001>。
还打不开就去 `.tools\logs\` 看 `site.err` 最后几行。

**Q：页面全是纯文字、图片是灰块？**
纯文字 = `.env` 里 `DEBUG` 被改成 `False` 了，改回 `True`。
灰块 = 封面图还没缓存，要么等它慢慢下，要么跑 `deploy\06_warm_images.ps1 -Apply`。

**Q：改了 `.html` 模板，网页还是老样子？**
本项目启动时关掉了自动重载，**改模板必须重启站点**（`stop-win.vbs` → 等几秒 → `start-win.vbs`）。
不是代码写错了，是模板被缓存了。

**Q：脚本只打印不干活？**
故意的。`deploy\` 里所有脚本默认**只检查**，要真动手得自己加 `-Apply`。

**Q：搜游戏一直转圈或报错？**
多半是连不上 `store.steampowered.com`（网络问题，不是部署失败）。
临时办法：先在游戏库页面用本地搜索顶一下。
